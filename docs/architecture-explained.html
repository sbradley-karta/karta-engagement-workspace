Engagement Delivery Workspace

What we are building, how it works, and where every piece lives

Each Karta engagement gets a workspace page that reads the tools the team already uses, drafts the weekly client status with Claude, and hands a finished PowerPoint deck to a named person who approves it. This page walks through every tool involved, what Karta hosts, and where client information does and does not go.

Where client data livesExactly where it lives today: Asana, SharePoint, Granola and Harvest.The workspace reads them as the consultant who is looking, with that consultant's own access. It keeps only the status values a person approved.
What Karta hostsTwo things: the workspace pages in Karta's Claude account, and a deck builder on Google Cloud.Spend to date on the cloud side is $0.36. Budget under $20 a month beyond the Claude seats the team already has.
What leaves KartaOnly a deck a named person approved, and only when that person chooses to send it.Nothing is sent automatically. Missing evidence shows as Unknown, never as Green.

1.0The big picture: every tool and where it lives

Five places. Read left to right: the consultant's desk, Karta's Claude account, Karta's systems of record, the small amount Karta hosts itself, and the client. Green arrows carry the approved status; dashed lines are connections planned but not yet used.

  1. Open the workspace. A consultant opens their engagement's page in claude.ai. The first time, the page asks permission to use their connectors.
  2. Read as the consultant. The page reads the Asana project and the SharePoint status folder with that consultant's own access. Granola, Harvest, Outlook and a RAID log are linked or planned; their reads come later.
  3. Draft on a click. Claude writes the week's narrative from what was read and suggests Green, Yellow or Red. Dates and status colors are calculated by code, not by Claude.
  4. Correct and approve under a name. The consultant edits anything wrong and approves. The record, with their name and time, is saved in the page's database.
  5. Build the deck. The approved values go to Karta Assembly, which fills the KCG template and returns a PowerPoint file. It keeps nothing.
  6. Save to SharePoint. The deck lands in the engagement's Status & Steer Co folder as the consultant. Until IT approves the sign-in, the page hands the file to the consultant to save instead.
  7. A person sends it. The consultant opens the deck in PowerPoint and sends it in Teams or email, as today. Software never sends.
  8. Sign-in. Microsoft Entra restricts the deck builder to Karta identities. One approval from IT is pending.
  9. Ship changes. Code lives in Karta's GitHub. From there the deck builder deploys to Google Cloud and the pages are published to claude.ai.

2.0A week of Weekly Status

What actually happens on a Friday. Seven steps across four places. The consultant only reads, corrects, approves and sends. Code does the dates, the colors and the file; Claude drafts the words.

6.0Words used on this page

ConnectorA permission a person grants once in claude.ai so Claude and the workspace can read a tool, such as Asana, on that person's behalf. Each person connects their own.
Engagement workspace pageA web page published from Karta's Claude account, one per engagement, that the staffed team opens in claude.ai. It is where Weekly Status happens.
Karta AssemblyKarta's own small service that turns approved values into a PowerPoint deck on the KCG template. It runs on Google Cloud and keeps nothing.
Entra IDMicrosoft's sign-in for the Karta tenant. Used so only Karta identities can call the deck builder, once IT approves the one-time request.
Cloud RunGoogle's service for running a small program only when it is called. Karta pays for seconds of use, which is why the bill rounds to zero.
Approved valuesThe set of numbers, dates, statuses and sentences a named person approved for one week's status. The only thing that ever goes to the deck builder.
Page databaseStorage attached to each workspace page, inside Karta's Claude account, holding approved records and the engagement's configuration.
GitHubWhere the code and documents that make all of this live, with a history of every change. Owned by Karta from the week of September 14.
